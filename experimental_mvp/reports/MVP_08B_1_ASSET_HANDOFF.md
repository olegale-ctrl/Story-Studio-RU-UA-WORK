# Recoverable asset/project handoff saga

EXISTING: Library commits files/catalog, attach writes historical links then mutates a supplied dictionary, Editor.asset_change CAS applies an in-memory candidate with Undo, pipeline.save atomically replaces JSON without a disk-revision CAS. None spans all resources. PROPOSED saga below must not be described as implemented atomic behavior.

## Durable resource roles

JobStore is job/event/attempt/approval/reservation authority; ArtifactStore owns verified retained bytes+validation manifests; Asset Library owns assets/revisions and historical link observations; GUI owns a live editor snapshot; **saved project JSON is current-binding authority**. ProjectSaveReceipt is evidence of a specific saved JSON version, not permanent truth about future edits. All markers bind job/attempt/artifact/SHA,asset exactrev,target snapshots,policy/approval and controller epoch. No marker is inferred from an unqualified filename, prompt equality, byte hash alone or historical links row.

## import_file mapping and gap OD02

Use only its existing accepted fields: source absolute stagingpath; provenance.source_type=DERIVED for synthetic simulator fixtures (not real AI claim), provider/model simulator namespace, provider_job_id namespaced, generation_timestamp fixture-clock value, prompt_reference protected reference, input_asset_references compact exactrefs≤256chars,source_sha256=resultSHA; rights explicitly UNKNOWN/PENDING or separately documented local experimental clearance; tags≤100chars include stable job/saga correlation strings. Cost,requested/resolved model,account/price/DFE/approval manifests belong to JobEvidence because extra provenance fields are rejected. import_timestamp remains Library-generated actual import time, distinct from deterministic simulator clock.

Import always creates a new Asset identity, even for same SHA; content dedup alone is not exactly-once asset registration. Search only current metadata and historical links, no unique ingest key. Proposal OD02: future Library extension with durable unique ingestion_token→asset receipt in the same Library transaction, plus qualification of concurrent callers. This branch adds no API or schema. Until approved/implemented, UNKNOWN import outcome **halts automatic handoff** for human reconciliation; never interpret zero tag matches as proof of no commit, since tags can change or lookup can be incomplete. A human can select a verified existing asset with explicit evidence; authorizing a new independent metadata record doesn't authorize generation or erase duplicate risk.

## P1-03 — project identity, CAS, undo and saved authority

Current UI project label derives from topic, not stable UUID. Proposed ProjectRef needs explicit stable UUID,canonical managed locator and saved-byte hash plus editor snapshot identity. OD03 decides opt-in identity/save coordination; never infer identity from title/path alone or mutate existing project schema here. Anchor expected token uses all fields; storyboard generation fingerprint is supplemental and insufficient. Tokens are content snapshots, not causal edit counters/ABA protection against a privileged writer.

Before apply, validate exact current asset revision/bytes/rights, live target IDs/token and editor snapshot, explicit replacement approval with prior-binding digest. Materially changed target → STALE_TARGET. Retain result/asset; do not silently update expected hashes or rebind to another anchor. Explicit rebase creates a new HandoffIntent with current target review, leaving original request immutable. All GUI apply events go through the existing history path and clear approved; Undo/Redo do not grant rights or restore old catalogue state.

Recovery after editor close: no Tk objects/callbacks assumed alive. Durable asset can remain ASSET_COMMITTED/ATTACH_PENDING, notify a new session by job IDs only; a fresh target review/CAS is required. After in-memory attach but before save, JSON old binding remains authoritative. Historical links cannot prove it was saved, and must not be “reconciled” by silently rewriting projects. If save already occurred, inspect actual JSON and validate exact receipt; a missing GUI acknowledgement may be recorded as RECOVERED_FROM_SAVED_READBACK only when the exact intended binding/version is proven, never fabricated as an observed GUI callback; if user saved another edit afterward, don't recover by overwriting it.

Rights revoked during execution → stop future side effects and request cancellation where qualified. Already produced bytes may be retained only under permitted quarantine/retention; no attach. Existing resolve checks aren't an atomic in-flight revocation gate. Unsupported cancellation and uncertain billing stay explicit NEEDS_RECONCILIATION. No code change claimed to close this risk.
