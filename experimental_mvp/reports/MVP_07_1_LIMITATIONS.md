# MVP-07.1 — ограничения и остаточные риски

- **WINDOWS_NOT_RUN.** STATIC_REVIEW_PASS и переносимые Linux-oracles не являются Windows PASS. Не квалифицированы ACL, file locks, antivirus, реальное Windows process termination, Tk/HiDPI и shell playback. RC-02 Windows gate не закрыт.
- Preview остаётся временным prerender, не синхронным встроенным player. Position preview заканчивается текущей сценой. Human listening, editorial/scientific review и права реальных production материалов не подтверждены.
- Для managed FFmpeg render/mux команд введена polling cancellation (50 ms) с terminate→wait 2 s→kill→wait 2 s fallback, только для созданного Popen handle. Реальные локальные тесты измеряют request→exit. Независимые FFprobe/short input-check `subprocess.run` и необязательный внешний TTS не превращены в универсальный cancellable process tree; их timeout/завершение может задержать общий ответ (обычно до 25 s для probe). Нельзя обещать немедленное завершение при uninterruptible OS I/O.
- Cancel/error удаляет только зарегистрированные UUID output folders конкретной preview session. UI дополнительно удаляет точный возвращённый result при late cancel/destroy. Успешные previews сохраняются для player; пригодный audio cache и user assets не удаляются. Если ОС отказывает в удалении (например Windows lock), surfaced error не является SUCCESS, но физический cleanup не гарантируется. Это не квалифицированный forensic/production storage.
- Atomic save явно использует UTF-8/LF (newline="") для переносимого readback и проверяет serialized payload/readback и делает fsync файла + replace после закрытия temp. Не заявляется power-loss durability каталогов/сетевых FS, защита от hostile concurrent writer после readback, Windows reparse points или все возможные OS faults. Non-finite NaN/Infinity теперь отвергаются до записи как невалидный JSON; опубликованные корректные проекты совместимы. Версия JSON/timeline не менялась.
- `allow_conflicts=True` — явное сохранение черновика с approved=False. Положительные, но семантически неверные source intervals/manual-map mismatch сохраняются для ремонта, но не экспортируются. Неверная shape (например negative duration или end≤start) по-прежнему отвергается при сохранении; previous file остаётся целым.
- Кадровая матрица A=30@24, B=60@25, C=120@30, D=180@30 полностью отрендерена и декодирована **в 160×90**. Использованы реальные 15/60 FPS clips, PNG, FIT/CROP, in/out, HOLD/LOOP и инженерная тишина. Это тест timeline/PTS, не качества фильма и не 1080p long-run performance. Длинные A–D **1080p stress: NOT_RUN**. Существующая 1080p функциональная регрессия остаётся в прежних тестах.
- Толеранс duration guard не ослаблен: max(0.1 s, 2/FPS). Номинальный и реально декодированный frame count, а также PTS packet grid проверяются отдельно. LOOP output явно использует уже заданный target FPS; скрытого speed change нет.
- Undo/Redo остаётся прежней transactional history, до 100 действий текущей timeline session; не создана вторая история, нет global cross-tab/crash recovery. Не добавлены архитектура MVP-08, waveform, ASR alignment или media automation.
- Hash/provenance/license поля сохраняются, но сами по себе не доказывают право использования. Каталог 13 providers, LLM/manual mode, quota rules и коммерческие условия не менялись; платные генерации не вызываются тестами.
- Внешний evidence bundle с MP4 публикуется только как workspace artifact с точным путём/SHA. Его наличие не означает GitHub upload/release. В GitHub входят отчёты, compact evidence и код отдельной ветки; окончательный post-commit manifest выдаётся с handoff.

Решение владельца — AUTHORIZED_EXPERIMENTAL для текущей стадии, не production permissions. После публикации ветки — **STOP** перед независимой приёмкой. MVP-08 в данной ветке не начат.
