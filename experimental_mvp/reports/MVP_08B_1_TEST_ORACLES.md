# Executable-ready acceptance oracle specifications

These are **specifications, not executable tests or passing results**. Each row is independently NOT_RUN. Future test implementation must supply the fixture/virtual clock/store/process hooks described in the simulator and failure matrix; no service credentials/network required. Common pass rule: every expected state/evidence/count/invariant must hold together and every forbidden side effect must be absent; a missing measurement,unexpected exception,hidden retry or native crash is FAIL, not a skipped success. Illegal transitions reject state mutation and retain a sanitized rejection event. No test may synthesize an approval/receipt merely to reach a state.

Unless an event explicitly states UNKNOWN billing, simulator negative fixtures have known settled zero billing. Expected-state case maps require the runner to choose the matching declared input case; they are not alternative acceptable outcomes for one input.

Initial states with slash/set describe explicitly distinct checkpoints under the same stated invariant; runner must expand them, preserving separate outcomes. ANY_NONTERMINAL for corruption means an untrusted store cannot authorize **any** effect, not a new legal job state. SM IDs reference the state-machine transition rules; SIM IDs reference fixture scripts; SG IDs are saga checkpoints. New APIs proposed by OD02/OD03/OD04 remain test preconditions, not mocked as if current guarantees existed. A stub receipt may test consumers, but cannot count as qualification of the producer's atomicity.
