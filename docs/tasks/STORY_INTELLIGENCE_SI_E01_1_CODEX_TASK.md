## 3. Exact new public APIs and semantics

### `story_intelligence/codec_v1.py`

Export:
- `canonical_si_json(value) -> bytes`
- `decode_canonical_si_json(data: bytes) -> plain JSON value`
- `canonical_si_sha256(value) -> str` (lowercase SHA-256 hex of exact canonical bytes)

Canonical C: UTF-8 without BOM; object keys sorted by Unicode codepoint order, no spaces, no implicit Unicode normalization, JSON arrays in supplied order, exact JSON primitive types only (`dict,list,str,int,bool,None`), no float/NaN/Infinity, no Python subclass coercion. Forbid lone Unicode surrogates, duplicate keys including escaped equivalent spellings, noncanonical whitespace/key order/number spellings/escaped-vs-raw forms, malformed UTF-8, and unbounded nesting. Preserve arbitrary-size JSON integers within byte limits without float conversion; bool must never satisfy an integer validator. Decoder must reject noncanonical bytes rather than silently normalizing them.

For this substage apply SI **single-object** limits: `<=1_000_000` UTF-8 bytes, `<=100_000` Unicode codepoints per string/key, max **32** nested containers. Reject over-limit input/output without truncation. The SI bundle limits (16 MiB/1000 records) are **not** implemented until a bundle interface exists; do not claim them tested.

The codec hashes arbitrary valid canonical JSON **as a byte primitive**. It does not certify a record's typed payload, provenance, content truth, rights or authority. Do not expose a function named `validate_record` or `record_ref` that could misleadingly imply full record validation.

### `story_intelligence/model_v1.py`

Export:
- `SIValidationError` with stable `code` and `path` (non-authorizing structural diagnostics).
- `validate_si_ref(value)` — closed `{type,id,revision,sha256}`, type from exact 18-record vocabulary; canonical lowercase hyphenated UUID, revision positive integer excluding bool, hash 64 lowercase hex.
- `validate_eref(value)` — closed `{kind,id,revision,content_hash}`; `kind` from actual existing editorial `ObjectKind` vocabulary (read-only), but do not equate ERef and SIRef or import editorial authority.
- `validate_known(value, value_validator)` — closed `{state:KNOWN,value:T}` or `{state:UNKNOWN,reason:Text}`; value_validator must validate KNOWN T, UNKNOWN never has value. Do not coerce UNKNOWN into 0, false, null or empty list.
- `validate_origin(value)` — exact R1 modes: MANUAL_INPUT, USER_IMPORT, RULE_DERIVED, TEMPLATE_DERIVED, MODEL_DERIVED, HUMAN_EDIT, RUN_METADATA; required nullable `run_ref`/`imported_from` with mode-dependent constraints. USER_IMPORT uses Known<Text> even when original source is UNKNOWN. For derived/edit modes `run_ref` is typed SIRef to RunRecord; RUN_METADATA is only valid for RunRecord H.
- `validate_header(value)` — closed full H: `si_version,type,id,revision,previous,created_at,creator_label,origin,input_refs,editorial_refs`. Validate exact required keys/no extras; `si_version` exactly integer 1; UTC seconds `YYYY-MM-DDTHH:MM:SSZ` with real calendar values; `creator_label` nonempty Text but not an OS identity; strict SIRef/ERef list elements and order. For revision1 `previous=null`; for later revision `previous` exact same type/id and revision-1. RunRecord has RUN_METADATA and revision1, creator_label `SI_ENGINE`; non-RunRecord must not use RUN_METADATA. Enforce only *local, provable* type/origin rules from original+R1+R1a (e.g. initial StoryIdea RULE_DERIVED, initial CreativeAlternative TEMPLATE_DERIVED; later HUMAN_EDIT requires previous). Do not invent cross-record evidence from unresolved refs.

All validators are pure and fail closed on unknown/missing keys, invalid types/versions, malformed UUID/hash/time, mode/ref mismatches, and wrong previous chain. They must not mutate inputs. Choose and document return value (validated copy or immutable value), consistently. Use only public diagnostic codes from R1 where a code is surfaced (`TYPE`, `LIMIT`, `MISSING_FIELD`, `UNKNOWN_FIELD`, `VERSION_UNSUPPORTED`, `PROVENANCE_MISMATCH`, `REF_TYPE_MISMATCH` as applicable); malformed canonical JSON may use structural `TYPE` with a clear message/path, **not new wire-interface codes**. Full reference resolution, exact hash verification against a record, DAG/closure, run-stage binding, selection/currentness and request idempotency are explicitly **deferred** to SI-E01.2.
